# 3. Folder Descriptions

## README.md

The main entry point for the repository.

Contents include:

- Project summary
- Installation
- Usage
- Results
- Documentation links

---

## docs/

Contains all technical documentation.

Purpose:

- Explain the architecture
- Document experiments
- Describe implementation details
- Provide reproducibility instructions

Target audience:

- Recruiters
- Researchers
- Contributors

---

## notebooks/

Contains interactive Jupyter notebooks used during development and experimentation.

Primary notebook:

```
Final_Experiment_Reproduction.ipynb
```

Responsibilities:

- Dataset loading
- Model initialization
- Training
- Evaluation
- Visualization

---

## figures/

Stores diagrams and visual assets used throughout the documentation.

Suggested organization:

```
figures/
│
├── png/
├── svg/
└── source/
```

Image categories:

- Repository Architecture
- Data Pipeline
- Model Architecture
- Training Pipeline
- Workflow Diagrams

---

## outputs/

Contains artifacts generated during experiments.

Examples:

```
outputs/

training_logs/

predictions/

evaluation/

model_summary.txt
```

These files should be reproducible and generally excluded from version control if they are large or generated automatically.

---

## report/

Contains the final project report and supporting material.

Example:

```
Final_Report.pdf
```

This document summarizes:

- Research background
- Methodology
- Results
- Conclusions

---

## original_repo/

Stores the original research implementation.

```
original_repo/

Taxi-Route-Recommender/
```

Important contents:

```
script/

gcn/

data/

results/
```

This directory should remain as close as possible to the original implementation to simplify comparison with the research paper.

---

## data/

Contains datasets required for reproduction.

Typical contents:

```
sample_input/

sample_last_dim_0.npz

sample_last_dim_1.npz

sample_last_dim_2.npz

sample_input.npy
```

Large datasets should not be committed to GitHub unless licensing permits.

---

## results/

Stores experiment outputs generated by the original repository.

Possible contents:

- Prediction files
- Metrics
- Evaluation outputs

# 8. Best Practices

- Keep documentation synchronized with code changes.
- Avoid modifying the original repository unless necessary.
- Use virtual environments for dependency isolation.
- Record experimental configurations.
- Commit source files for diagrams alongside exported images.
- Separate generated outputs from source code.

# 10. Quick Start for Contributors

1. Clone the repository.
2. Create a Python 3.10 virtual environment.
3. Install dependencies.
4. Reconstruct `sample_input.npy` if required.
5. Verify the working directory.
6. Run `Final_Experiment_Reproduction.ipynb`.
7. Compare outputs with the expected results documented in `Experiment.md`.
8. Consult `Challenges.md` if issues occur.
9. Submit improvements through pull requests.

---

# Repository Design Principles

The repository is organized according to the following principles:

- **Modularity:** Separate documentation, code, data, and outputs.
- **Reproducibility:** Clear setup instructions and reproducible experiments.
- **Maintainability:** Logical directory hierarchy and consistent naming.
- **Transparency:** Comprehensive documentation of implementation details and engineering decisions.
